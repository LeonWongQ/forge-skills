# Template: Explanation

## Purpose

Use this template when the primary task is conceptual explanation or mechanism clarification.

This template is designed for outputs that must communicate:
- what something is
- why it matters
- how it works
- an example
- common misunderstandings or pitfalls

It is appropriate for:
- framework explanation
- architecture concept clarification
- tradeoff explanation
- code-path mechanism explanation
- compare-and-contrast explanations

---

## Output Structure

### 1. What it is
Provide a concise definition.

### 2. Why it matters
Explain practical significance.

### 3. How it works
Describe the mechanism in a logical order.

### 4. Example
Give a concrete example.

### 5. Common pitfalls or misunderstandings
Call out what users often get wrong.

### 6. Optional deeper detail
Include only if useful for the user's likely depth needs.

---

## Style Guidance

- explain for understanding, not recital
- use plain but correct language
- build a mental model before deep detail
- include examples
- surface the most important misconception

---

## Good Fit Examples

Use this template for:
- explaining Spring proxy behavior
- explaining cache-aside semantics
- explaining Playwright flakiness causes
- explaining transaction propagation
- explaining tradeoffs between two designs

---

## Avoid

Avoid using this template when the task is primarily:
- code review findings
- phased refactor design
- formal implementation plan
- incident-style debugging

---

## Short Reminder

Explanation template means:
- define it
- explain why it matters
- show how it works
- give an example
- call out the common mistake
